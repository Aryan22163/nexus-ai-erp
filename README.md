## 🌟 Vision & Overview

**NEXUS AI** transforms business operations from manual, siloed menu navigation into an **AI-first, intent-driven operating system**. Users can seamlessly run day-to-day operations through either a responsive enterprise UI or through an **AI Copilot** that:
- Understands organization-wide business context across all operational departments.
- Aggregates multi-dimensional business data safely and securely.
- Performs predictive forecasting, churn detection, and anomaly recognition.
- Proposes mutating operational actions (creating sales orders, purchase requests, invoices) with **strict Human-in-the-Loop (HITL) approval gates**.
- Enforces strict multi-tenant row-level isolation and role-based permissions (RBAC).

## 🚀 Quickstart Guide

### Prerequisites
- Python 3.12+
- Node.js 20+
- Docker & Docker Compose
- PostgreSQL 16 with `pgvector` & Redis (or run via Docker)

### Option 1: Run with Docker Compose (Recommended)

```bash
# 1. Clone the repository and navigate to root
cd "nexus-ai"

# 2. Configure environment
cp .env.example .env

# 3. Start all services
docker-compose up --build
```
The application will be accessible at:
- **Live Production App (Vercel)**: [https://nexus-ai-erp-hazel.vercel.app](https://nexus-ai-erp-hazel.vercel.app)
- **Local Application Server**: `http://127.0.0.1:8000/app/`
- **Frontend UI (Next.js)**: `http://localhost:3000`
- **Backend API Docs**: `http://localhost:8000/docs`

## 🛡️ Security & Privacy Guardrails

1. **Strict Multi-Tenancy**: Every entity is scoped by `organization_id`. Tenant boundaries are verified at the database session and vector retrieval levels.
2. **Human-in-the-Loop (HITL)**: Mutating business actions generated by AI require explicit interactive human approval before execution.
3. **Read-Only NL-to-SQL**: Natural language querying utilizes an allowlisted AST validator (`SELECT` statements only, strict timeouts, row caps).
4. **Audit Logging**: All state mutations record actor, IP, timestamp, and before/after diff snapshots.
